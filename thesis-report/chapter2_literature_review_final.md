# Chapter 2 Literature Review

## 2.1 House Rental Management Systems
Recent studies show that web-based rental systems improve discoverability, reduce manual coordination, and provide faster rental services for tenants and property owners (Monteverde et al., 2023; Obse, 2025; Wahab et al., 2025). Research has also extended rental systems with structured booking workflows and integrated information architecture to reduce fragmented search and booking processes (Indrayani & Istikomah, 2026; Muharam et al., 2024).

From an engineering perspective, rental platforms increasingly combine property listing, tenant-side filtering, request submission, and transaction monitoring in one interface. This integration is important because unstructured data and subjective manual processes remain common bottlenecks in rental decision-making (Setiawan et al., 2026).

## 2.2 Web-Based Information System Development
Web-based information systems are commonly developed through iterative or prototyping-oriented methods when requirements evolve during implementation (Riyanti et al., 2024). In rental contexts, such methods are frequently used to align interface flow, role behavior, and transaction states with real operational needs (Upadhyay et al., 2025; Wang et al., 2026).

In addition, data-driven recommendation features have been introduced to support rental selection quality and decision consistency. A web-based recommendation approach using hierarchical fuzzy axiomatic design demonstrates how multi-criteria decision factors can be operationalized in rental matching workflows (Şenyüzlüler & Baykasoglu, 2024).

## 2.3 Rental Transactions and Property Platform Dynamics
Beyond system implementation, property-rental research also highlights platform-level dynamics, including platformization, extraction behavior, and changing relationships between tenants, landlords, and intermediaries (Rogers et al., 2024; Wainwright, 2022). These findings justify the need for transparent transaction states and auditable histories in rental systems.

Short-term rental data studies further show that high-frequency operational data can strengthen evidence-based monitoring and policy analysis (Wang et al., 2024). For this thesis, the implication is that rental transaction records should be structured from the start so they are reusable for operational analytics and decision support.

## 2.4 Role-Based Access Control in Web Applications
Role-based access control (RBAC) remains a core requirement in multi-actor web applications. Le et al. (2022) emphasize that broken access control is a major web security issue and that policy inconsistencies are common in poorly documented systems. In house rental platforms, this risk directly affects data confidentiality, authorization boundaries, and transaction integrity across admin, agent, and tenant roles.

Therefore, access control in this research is positioned not only as a login/permission feature but as a process-control mechanism tied to state transitions and role responsibilities.

## 2.5 Data Analysis and Decision Support in Rental Systems
Rental decision support research demonstrates that structured criteria and objective ranking models can reduce subjectivity in property selection (Setiawan et al., 2026). This supports the inclusion of analyzable transaction data fields, status histories, and role activity logs in the system data model.

User adoption research in boarding-house rental applications also indicates that user trust, usability, and perceived usefulness influence platform acceptance (Pritalia et al., 2025). Thus, system success is not determined only by feature completeness, but also by clarity of workflow and reliability of user-facing information.

## 2.6 Iterative Prototyping in Rental System Development
Methodology selection is a recurring issue in rental-system studies because user workflows and role interactions are often refined during development. Existing studies report that iterative and prototype-driven cycles help teams validate interface behavior and transaction flow earlier in implementation (Monteverde et al., 2023; Obse, 2025).

Monteverde et al. (2023) describe a Rapid Application Development process with a prototype cycle where implementation and evaluation are repeated to improve the rental platform. Obse (2025) similarly applies throwaway prototyping to align design decisions with operational requirements before final system integration. These findings show that in rental platforms, development is often more effective when feedback loops are embedded into the process.

In contrast, waterfall-based implementations are also present in the same domain and provide structured sequential stages from requirements to maintenance (Wahab et al., 2025). However, this model is less flexible when requirement changes emerge during module implementation. Therefore, this thesis positions its development approach closer to iterative prototyping, where modules are built, evaluated, and revised in cycles until functional expectations are met.

## 2.7 Research Gap and Positioning
Based on prior studies, three practical gaps remain. First, many rental applications focus on search and booking but provide limited end-to-end transaction control. Second, role and status governance are often discussed separately, while operationally they must be integrated. Third, rental platforms often underutilize transaction records for decision support.

This thesis addresses these gaps by developing a web-based house rental management system that integrates: (1) lifecycle-based rental workflow, (2) role-based authorization, and (3) structured transaction data for operational monitoring and future analytics.
